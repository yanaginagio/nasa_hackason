# Jezero Traverse

Perseveranceの左Navcam画像7枚と、ジェゼロ・クレーターの実走行線を再生する36秒のゲームです。Sol 16・20・23の各走行の前に、NASAの記録（地形の傾き・現地時刻と日照・画像の到着）を見て走行計画を決めます。

## 起動

リポジトリのルートで実行し、ブラウザで http://localhost:8417/ を開きます。

```sh
python3 -m http.server 8417 --bind 127.0.0.1 --directory rover-replay
```

画像・地図タイル・データは `assets/` に同梱されています。起動後の外部アクセスやAPIキーは不要です。素材の再取得はネット接続のある環境で `python3 tools/prepare_rover_replay.py` を実行します。

## 遊び方

走行の前ごとに再生が止まり、計画の画面が出ます。間違えるとヒントが出て選び直せます。途中で1回、実際に火星ローバーで起きたアクシデントが起き、対応策を自由記述で答えます。

### 電力

電力（バッテリー）が0%になると失敗です。値は `game.js` の `RULES.power` で変えられます（すべてゲーム用の設定）。

| 増減 | 量 |
|---|---|
| 計画を考えている間 | 実時間1秒ごとに −1% |
| アクシデントに答えている間 | 実時間1秒ごとに −1.5% |
| 計画の選択を間違える | −12% |
| アクシデントの回答が不十分 | −8% |
| アクシデントの答えを見る | −20% |
| 走行 | 1 mごとに −0.25%、登り1 mごとに −4%（PLACESの距離と標高から） |
| 走行の間の休止 | 1 solごとに +3%（MMRTGによる充電） |

### 大型イベント

ミッションとは別に、実際の観測を専用の画面で見せます。`assets/events.json` に内容を入れ、7秒目に「大型イベント発生」の演出のあと画面が切り替わります。いまは1件です。

- ダストデビル（つむじ風）：Perseverance の Navcam が 2023年8月30日（Sol 899）に撮影した GIF（21コマ・4秒おき・20倍速、NASA/JPL-Caltech、PIA26074）。数値（距離約4 km・速さ約19 km/h・幅約60 m・写っている高さ約118 m・影から見積もった高さ約2 km）は NASA の記事どおりです。パノラマ上の位置に丸印を付け、拡大した画像も添えています。
- 問題（高さを何から見積もったか）に正解すると探査画面に戻ります。間違えると電力 −5%。イベントの画面を見ている間は電力は減りません。
- 素材は `assets/events/dust-devil-sol899.gif`（約6.2 MB）。走行区間（Sol 15〜23）とは別の時期の観測なので、画面に観測日を出しています。

### アクシデント

`assets/accidents.json` に、実際の事例と実際の対応策を5件入れてあります（Spirit の右前輪の故障、Opportunity の砂への埋まり、Curiosity のコンピュータ切り替え・車輪の損傷・ドリルの故障）。毎回1件をランダムに出します。画面の「アクシデント（テスト版）」か、URLの `?accident=wheel` などで固定できます。

採点は `grader.js` のキーワード一致です。事例ごとに観点（例：「後ろ向きに走る」「壊れた車輪を引きずる」）とその言い換えを持ち、`min` 個以上の観点が入っていれば正解です。ひらがなとカタカナ、全角と半角は区別しません。後でローカルの埋め込みモデルによるコサイン類似度の採点に替えるときは、`gradeAnswer` を同じ戻り値（`passed`・`matched`・`missing`）のまま差し替え、参照解答には各事例の `answer` を使います。

| 計画 | 見るデータ（実データ） | 判断の基準（ゲーム設定） |
|---|---|---|
| Sol 16 の走行 | 区間の最大の傾き・標高差（PLACES） | 傾き3°以上の地点を含むなら、視覚オドメトリで滑りを確かめながら走る |
| Sol 20 の走行 | 走行開始の現地時刻、前回の速さから見積もった終了時刻、太陽高度（PLACES・Navcamラベル） | LMST 15:30 までに走り終える |
| Sol 23 の走行 | 前回終点の画像が地球に届いた時刻と、次の走行の時刻（Navcamラベル） | 前方を画像で確かめてから計画する |

正解は `game.js` の `RULES` の値と `mission.json` のデータから、その場で計算しています。基準値を変えれば正解も変わります。計画を送ると、実際の走行の記録（時刻・距離・所要時間）が出ます。

画面は Navcam の画像を全面に敷き、右上に走行マップを重ねています（幅780px以下では縦に並べます）。「ローバーの状態」（左上）とミッション欄（下）は、イベントのときだけ出します。

| 場面 | 出るもの |
|---|---|
| 走行中 | 画像・マップ・下の細い帯（電力・進み具合・一時停止）。計画やアクシデントの結果は数秒だけ通知で出ます |
| 走行計画 | ローバーの状態＋ミッション欄。その計画で使う項目だけが光り、ほかは暗くなります |
| アクシデント | ミッション欄（回答欄） |
| 大型イベント | 専用の画面に切り替わります（下記） |

「ローバーの状態」は判断に使う値を図で示します。

- 現地時刻と太陽：6〜18時の帯の上を太陽が動きます。点線は走行終了の基準（15:30）です。
- 地形の傾き：前後・左右の傾きをローバーの絵で示します（4倍に誇張）。バーは基準3°との比較、下の折れ線は出発地点からの標高です。
- 方位：コンパスに、進む向き（矢印）と太陽の方角（黄色の点）を示します。
- 画像が地球に届くまで：いま表示中の画像の、撮影から地球で受信するまでの時間です。

時刻・傾き・標高・方位は走行記録を走行線に沿って補間した値、太陽と受信までの時間は、いま表示している画像のラベルの値です。温度は判断に使わないので、表示から外しました（`mission.json` には残っています）。

## データ

- [NASA PDS 左Navcam閲覧画像](https://planetarydata.jpl.nasa.gov/img/data/mars2020/mars2020_navcam_ops_raw/browse/)からSol 15〜23の7枚を選び、ファイル名のSCLKで撮影順を確認しています。
- 同じ画像の[PDS4ラベル](https://planetarydata.jpl.nasa.gov/img/data/mars2020/mars2020_navcam_ops_raw/data/)から、撮影時の現地平均太陽時（LMST）、太陽の高度と方位（SITE座標系＝北基準）、Navcamとロボットアーム関節の温度、撮影時刻（UTC）と地球での受信時刻を読みます。温度は機器の温度で、気温ではありません。
- [PDS Rover PLACES](https://pds-geosciences.wustl.edu/missions/mars2020/places.htm)で、同じSite/Driveのうち画像時刻に最も近いローバー位置を使います。撮影位置の近似で、位置記録と撮影の時刻差は `assets/mission.json` に残しています。走行線の69頂点は PLACES の Drive 386〜792 の記録と1対1で対応し（0.5 m 以上ずれたら素材づくりを止めます）、各頂点の傾き（roll・pitch）・方位（yaw）・標高を使います。走行の時刻は、SCLKの差を同じsolの画像のLMSTからの経過に換算しています（1 sol = 88,775.244 秒）。
- [NASA/JPLのMMGIS走行線](https://mars.nasa.gov/mmgis-maps/M20/Layers/json/M20_traverse.json)から対象の3区間を使います。ピンは撮影地点の間を走行線に沿って補間します。画像は6秒間隔で切り替わります。
- 背景は[NASA Mars TrekのJezero HiRISE WMTS](https://trek.nasa.gov/tiles/apidoc/trekAPI.html?body=mars)です。必要な2タイルを保存し、WMTSのタイルグリッドで走行線と位置を合わせています。
- 判断の基準値（傾き3°、LMST 15:30）・選択肢・電力の増減はゲーム用の設定です。アクシデントの出来事と対応策は実際の事例で、出典を `assets/accidents.json` に入れてあります。ゲームでは Perseverance に起きたものとして出題します。Sol 23 の判断では、計画を送る時刻の代わりに走行開始の時刻を使っています。
