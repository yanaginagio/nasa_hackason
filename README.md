# Jezero Traverse

Perseverance の打ち上げ・火星への航行・着陸を NASA の実映像と軌道データでたどり、着陸後はジェゼロ・クレーターの実走行線を再生する36秒の探査ゲームに続きます。Sol 16・20・23の各走行の前に、NASAの記録（地形の傾き・現地時刻と日照・画像の到着）を見て走行計画を決めます。

## 起動

リポジトリのルートで実行し、ブラウザで http://localhost:8417/ を開きます。

```sh
python3 -m http.server 8417 --bind 127.0.0.1
```

画像・地図タイル・データは `assets/` に同梱されています。起動後の外部アクセスやAPIキーは不要です。素材の再取得用スクリプトは、移動前の[コミットの `tools/`](https://github.com/yanaginagio/nasa_hackason/tree/39522af68d290b9f1cf4d3dca7c7d8f59e0dd0d1/tools)にあります。再取得する場合は、そのコミットを別の作業コピーに展開して、スクリプトを実行します。

## 物語の流れ

タイトル画面右上の「日 / EN」で日本語と英語を切り替えられます。選択はブラウザに保存されます。英語表示ではアクシデントの自由記述も英語で回答できます。

1. 打ち上げ → 2. 火星への航行 → 3. 着陸 → 4. 探査（走行の計画とアクシデント） → 5. 採取（ゴールで岩石を採る）。最初の画面の「ミッション開始」で1から、「探査から始める」で4から遊べます。URL の `?scene=cruise`（航行から）・`?scene=landing`（着陸から）でも始める場面を選べます。

### プロローグ（打ち上げ・航行・着陸）

`voyage.js`・`voyage.css`。探査画面と同じ部品（上の帯・ゲージ・丸い地図・状態の表示・通信カード・進行バー）を使います。右上の「スキップ」で場面を飛ばせ、「×1・×2・×4」で映像と演出を早送りでき、Space で一時停止します。

| 場面 | 内容 | 使うデータ |
|---|---|---|
| 打ち上げ | 5秒のカウントダウンのあと、発射台カメラの実映像（音も実際のもの） | NASA の打ち上げ中継映像（ISO B-roll） |
| 上昇 | ロケット第1段の機体カメラの実映像（2倍速）。固体ロケットブースターの切り離しから地球の丸みまで。経過時間は映像の時刻から出し、地球を回る登録物体の数も示します | 同上、NASA 軌道デブリ季報 2020年11月号（21,293 個） |
| 探査機の分離 | 上段ロケット Centaur のカメラの実映像（1.5倍速） | 同上 |
| 航行 | 203日を約20秒で。日付・地球と火星からの距離・速さ・電波の片道時間・進んだ道のりと太陽系の地図。途中で、打ち上げの週に地球のそばを通った小惑星・旅の半分・太陽フレア（2020-11-29、M4.4）・火星への接近を示します | JPL Horizons（探査機 -168・地球・火星、1日ごと）、NASA NeoWs、NASA の記事 |
| 突入 | 突入の速さ（時速 約19,500 km）・約7分・電波の片道 11分20秒 | NASA/JPL の解説、Horizons |
| 着陸（前半） | 機体カメラの実映像。管制室の読み上げから、速さ・高度・段階と日本語字幕を出します | NASA/JPL-Caltech の映像と字幕ファイル |
| **着陸地点へ回避（ゲーム）** | バックシェル分離（高度約2.6 km）からスカイクレーン（約20 m）まで。NASA が着陸用に作った実際の危険度マップの上で、赤（危険）と黄（注意）を避けて降ります。降りるほど地図が大きくなり、風（南東向きが多い）が強まります。最後は緑の輪（実際の着陸地点）を目指します。右下の小窓に、同じ時間帯の実際の映像が流れます | NASA PIA23970（危険度マップ）、管制の読み上げ（高度・速さ） |
| 着陸（後半） | スカイクレーンから着地までの実映像 | NASA/JPL-Caltech |
| 探査開始 | 着陸の結果を表示した後、走行開始時の Navcam 画像に sol と LMST を説明するシナリオを表示します。右下の ▶ で走行に進みます | — |

- ゲームを1つに絞り、実際の道のりでいちばん難しかった「着陸地点の危険をよける」場面にしました。着陸の責任者 Allen Chen は、ジェゼロ・クレーターを「これまでで最も危険な着陸地点」と呼んでいます（Astronomy 誌）。崖・岩の多い場所・砂丘があり、地形相対航法（機体のカメラの画像を地図と照らし合わせて位置を知り、危険を避ける仕組み）で降りました。
- 「機体の状態」は赤の上で1秒ごとに 26%（降りるほど増える）、黄の上で 6% 減り、赤の上に着地すると 35% 減ります。0% でやり直しです。風の強さを含め、ゲーム用の設定です（`voyage.js` の `TRN`）。地図の画像そのままの色で判定しているので、何も操作しないと失敗し、最適な道筋をとれば無傷で降りられることを確かめてあります。
- Horizons の軌道から計算した道のりは 4億7,020万 km で、NASA の発表（4億7,200万 km）との差は 0.4% です。
- 太陽フレアの一覧（DONKI）は、作業時に API が応答しなかったため、日付と規模は記事から取りました。

### AI で作ったものの表示

ハッカソンの規定に合わせ、AI で作ったものはその旨を画面に出しています。

- プロローグの左上の札で、いま見ているものを示します。「実写：NASA の映像」「AI生成のCG（実写ではありません）」（航行・突入の絵）「地図：NASA／機体と演出：AI生成のCG」（着陸のゲーム）。
- 結果画面の紙吹雪と花火、効果音、探査画面の図とアイコンも AI（Claude）が作ったものです。最初の画面・探査画面の下・結果画面に書いています。
- 写真・映像・録音・データはすべて NASA などの実物で、AI で作り変えてはいません（切り出し・縮小・速度の変更だけ）。

移動前の作業コピーで航行素材を再取得するには、`python3 tools/prepare_voyage.py --ffmpeg <ffmpeg のパス>` を実行します。`assets/voyage.json` と危険度マップ（`assets/voyage/jezero-hazard-pia23970.jpg`）を作り、NASA の映像から必要な区間だけを切り出して `assets/voyage/*.mp4`（計 14 MB、960×540）を作ります。映像の区間は `tools/prepare_voyage.py` の `CLIPS` にあります。

### 結果画面

`result.js`・`result.css`。ミッションが終わると（成功・失敗とも）出ます。

- 点数：着陸のゲーム（最大200）・走行計画（各100）・アクシデント（200）・大型イベントの問題（100）・採取（100）。1回目で正解すると満点で、合計の割合で S〜D のランクを付けます（ゲーム用の設定）。探査から始めた場合、着陸は点数に含めません。
- 復習：間違えた問題（と、たどり着けなかった計画）を開いて、自分の選択・なぜ違うか・判断の基準・実際の対応を確かめ、その場でもう一度解けます。アクシデントは自由記述で書き直すと、ゲームと同じ方法で採点します。
- 成功したときは、光の帯・紙吹雪・花火・ファンファーレで祝います。

## 遊び方

走行の前ごとに再生が止まり、計画の画面が出ます。間違えるとヒントが出て選び直せます。途中で1回、実際に火星ローバーで起きたアクシデントが起き、対応策を自由記述で答えます。

### 電力

電力（バッテリー）が0%になると失敗です。値は `game.js` の `RULES.power` で変えられます（すべてゲーム用の設定）。

| 増減 | 量 |
|---|---|
| 計画を考えている間 | 実時間1秒ごとに −1% |
| アクシデントに答えている間 | 実時間1秒ごとに −1.5% |
| 計画の選択を間違える | −12% |
| アクシデントの回答が不十分 | −8% |
| アクシデントの答えを見る | −20% |
| 走行 | 1 mごとに −0.25%、登り1 mごとに −4%（PLACESの距離と標高から） |
| 走行の間の休止 | 1 solごとに +3%（MMRTGによる充電） |

### 大型イベント

ミッションとは別に、実際の観測を専用の画面で見せます。`assets/events.json` に内容を入れ、7秒目に「大型イベント発生」の演出のあと画面が切り替わります。いまは1件です。

- ダストデビル（つむじ風）：Perseverance の Navcam が 2023年8月30日（Sol 899）に撮影した GIF（21コマ・4秒おき・20倍速、NASA/JPL-Caltech、PIA26074）。数値（距離約4 km・速さ約19 km/h・幅約60 m・写っている高さ約118 m・影から見積もった高さ約2 km）は NASA の記事どおりです。パノラマ上の位置に丸印を付け、拡大した画像も添えています。
- 問題（高さを何から見積もったか）に正解すると探査画面に戻ります。間違えると電力 −5%。イベントの画面を見ている間は電力は減りません。
- 素材は `assets/events/dust-devil-sol899.gif`（約6.2 MB）。走行区間（Sol 15〜23）とは別の時期の観測なので、画面に観測日を出しています。

### アクシデント

`assets/accidents.json` に、実際の事例と実際の対応策を5件入れてあります（Spirit の右前輪の故障、Opportunity の砂への埋まり、Curiosity のコンピュータ切り替え・車輪の損傷・ドリルの故障）。毎回1件をランダムに出します。画面の「アクシデント（テスト版）」か、URLの `?accident=wheel` などで固定できます。

採点は `grader.js` のキーワード一致です。事例ごとに観点（例：「後ろ向きに走る」「壊れた車輪を引きずる」）とその言い換えを持ち、`min` 個以上の観点が入っていれば正解です。ひらがなとカタカナ、全角と半角は区別しません。後でローカルの埋め込みモデルによるコサイン類似度の採点に替えるときは、`gradeAnswer` を同じ戻り値（`passed`・`matched`・`missing`）のまま差し替え、参照解答には各事例の `answer` を使います。

| 計画 | 見るデータ（実データ） | 判断の基準（ゲーム設定） |
|---|---|---|
| Sol 16 の走行 | 区間の最大の傾き・標高差（PLACES） | 傾き3°以上の地点を含むなら、視覚オドメトリで滑りを確かめながら走る |
| Sol 20 の走行 | 走行開始の現地時刻、前回の速さから見積もった終了時刻、太陽高度（PLACES・Navcamラベル） | LMST 15:30 までに走り終える |
| Sol 23 の走行 | 前回終点の画像が地球に届いた時刻と、次の走行の時刻（Navcamラベル） | 前方を画像で確かめてから計画する |

正解は `game.js` の `RULES` の値と `mission.json` のデータから、その場で計算しています。基準値を変えれば正解も変わります。計画を送ると、実際の走行の記録（時刻・距離・所要時間）が出ます。

画面は Navcam の画像を全面に敷き、探査車の機体が写りにくい左上（空のあたり）に円形のミニマップ、上の中央に電力のゲージを重ねています（幅780px以下では縦に並べます）。

- ミニマップ：進む向きが常に上になるように回ります。中央の矢印がローバー、外周の赤い N が北です。次のイベントの地点は脈打つ輪で示します。押すか M キーで全体の地図（北が上）を開き、M か Esc で閉じます。
- 電力：10目盛りのゲージです。ミスや充電で増減した分は「−12%」のように浮かんで見え、25%以下になると赤く点滅して警告音が鳴ります。
- 進行バー：画面のいちばん下。走行計画（ひし形）・アクシデント（赤）・大型イベント（青）の地点に印があり、済んだものは薄くなります。
- キー操作：1〜3 で選択肢を選ぶ、M で地図、Space で一時停止・再開。

| 場面 | 出るもの |
|---|---|
| 走行中 | 画像・ミニマップ・電力・進行バー。計画やアクシデントの結果は数秒だけ通知で出ます |
| 走行計画 | 右にローバーの状態、下に通信カード（橙）。その計画で使う項目だけが光り、ほかは暗くなります |
| アクシデント | 通信カード（赤）と回答欄 |
| 大型イベント | 専用の画面に切り替わります（下記） |

### 音

- 走行中：Perseverance が Sol 16（2021年3月7日）に走ったときの実際の音。EDL マイク（着陸用に積んだマイク）で録った約16分の録音から NASA が3か所を選び、雑音を減らした90秒版です。ゲームの最初の区間（Drive 386→578、約27 m）と同じ走行です。計画やアクシデントで止まっている間は鳴りません。出典：[NASA/JPL-Caltech](https://science.nasa.gov/resource/sounds-of-perseverance-mars-rover-driving-sol-16-90-second-highlights/)（`assets/audio/drive-sol16.mp3`）
- いつも小さく：着陸の約18時間後（Sol 1）に SuperCam のマイクが録った音。マストをたたんだままだったのでこもっていて、かすかに風が聞こえます。出典：[NASA/JPL-Caltech/LANL/CNES/CNRS/ISAE-Supaero](https://science.nasa.gov/resource/first-audio-recording-of-sounds-on-mars/)（`assets/audio/wind-sol1.mp3`）
- 効果音（計画の着信・アクシデントの警報・大型イベント・正解・不正解・電力の警告・成功・失敗）は、`audio.js` が Web Audio でその場で合成しています（音声ファイルなし）。
- 右上の「音 オン／オフ」で切り替えられます。ブラウザの決まりで、音は最初に「走行開始」などを押した後から鳴ります。

「ローバーの状態」は判断に使う値を図で示します。

- 現地時刻と太陽：6〜18時の帯の上を太陽が動きます。点線は走行終了の基準（15:30）です。
- 地形の傾き：前後・左右の傾きをローバーの絵で示します（4倍に誇張）。バーは基準3°との比較、下の折れ線は出発地点からの標高です。
- 方位：コンパスに、進む向き（矢印）と太陽の方角（黄色の点）を示します。
- 画像が地球に届くまで：いま表示中の画像の、撮影から地球で受信するまでの時間です。

時刻・傾き・標高・方位は走行記録を走行線に沿って補間した値、太陽と受信までの時間は、いま表示している画像のラベルの値です。温度は判断に使わないので、表示から外しました（`mission.json` には残っています）。

## データ

- [NASA PDS 左Navcam閲覧画像](https://planetarydata.jpl.nasa.gov/img/data/mars2020/mars2020_navcam_ops_raw/browse/)からSol 15〜23の7枚を選び、ファイル名のSCLKで撮影順を確認しています。
- 同じ画像の[PDS4ラベル](https://planetarydata.jpl.nasa.gov/img/data/mars2020/mars2020_navcam_ops_raw/data/)から、撮影時の現地平均太陽時（LMST）、太陽の高度と方位（SITE座標系＝北基準）、Navcamとロボットアーム関節の温度、撮影時刻（UTC）と地球での受信時刻を読みます。温度は機器の温度で、気温ではありません。
- [PDS Rover PLACES](https://pds-geosciences.wustl.edu/missions/mars2020/places.htm)で、同じSite/Driveのうち画像時刻に最も近いローバー位置を使います。撮影位置の近似で、位置記録と撮影の時刻差は `assets/mission.json` に残しています。走行線の69頂点は PLACES の Drive 386〜792 の記録と1対1で対応し（0.5 m 以上ずれたら素材づくりを止めます）、各頂点の傾き（roll・pitch）・方位（yaw）・標高を使います。走行の時刻は、SCLKの差を同じsolの画像のLMSTからの経過に換算しています（1 sol = 88,775.244 秒）。
- [NASA/JPLのMMGIS走行線](https://mars.nasa.gov/mmgis-maps/M20/Layers/json/M20_traverse.json)から対象の3区間を使います。ピンは撮影地点の間を走行線に沿って補間します。画像は6秒間隔で切り替わります。
- 背景は[NASA Mars TrekのJezero HiRISE WMTS](https://trek.nasa.gov/tiles/apidoc/trekAPI.html?body=mars)です。必要な2タイルを保存し、WMTSのタイルグリッドで走行線と位置を合わせています。
- 判断の基準値（傾き3°、LMST 15:30）・選択肢・電力の増減はゲーム用の設定です。アクシデントの出来事と対応策は実際の事例で、出典を `assets/accidents.json` に入れてあります。ゲームでは Perseverance に起きたものとして出題します。Sol 23 の判断では、計画を送る時刻の代わりに走行開始の時刻を使っています。
